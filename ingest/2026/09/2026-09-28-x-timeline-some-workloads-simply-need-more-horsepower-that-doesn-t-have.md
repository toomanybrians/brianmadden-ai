# Some workloads simply need more horsepower.

That doesn’t have to mean creating

## Insights

- Argues that centralized IT platforms no longer need to force a single standardized experience on all users; modern architectures separate governance (identity, policy, security) from execution (where compute actually runs).
- Frames "power users" (developers, engineers, analysts, traders) as historically handled via exceptions — custom builds, local data copies, isolated access — which created security gaps and operational sprawl over time.
- Proposes a persona-based model of the workforce: SaaS-only workers, task workers, knowledge workers, and power users, each with different device/compute needs but unified control.
- Describes a shift in security models from device-trust to identity/context-based "security follows the work," enabling high-performance local compute without sacrificing centralized data protection.
- Cites financial services as an example where traders/analysts get low-latency local compute while risk/compliance teams use governed centralized environments, all under one control plane.
- Positions flexible consumption models (e.g., pooled credits, tiered service levels) as the mechanism letting IT right-size delivery per persona rather than applying one-size-fits-all entitlements.

## Quote

> Centralized platforms don't eliminate power users, they finally enable them.
