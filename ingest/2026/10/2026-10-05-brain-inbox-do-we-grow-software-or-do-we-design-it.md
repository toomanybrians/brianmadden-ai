# Do We Grow Software or Do We Design It?

## Insights

- Frames two contrasting approaches to building software with AI: "vibe-coding" (iterative, exploratory, organic — described via a petri-dish metaphor of trial and error) versus "designed" software (explicit state-machine/flowchart design).
- Describes advanced vibe-coding practice as running 4-5 parallel variants ("petri dishes") and selecting whichever one evolved best, rather than specifying a single correct path upfront.
- Argues designed software in the AI era means co-creating explicit state machines with AI: laying out every decision fork (e.g., email triage: archive/CRM/escalate) in a table so gaps become visible immediately.
- Claims this flowchart-based approach enables formal verification — mathematically proving the software behaves as intended — citing Boris Cherny's work formally verifying the Claude Agent SDK using Lean and TLA+.
- Positions the two modes along a spectrum: vibe-coding as organic and flexible, state-machine design as mechanical/rigid but necessary for core systems that must work reliably.
- Situates these as new entries in the lineage of software engineering philosophies, alongside test-driven development, pair programming, and "move fast and break things."

## Quote

> Growing software is organic. We can just program! State-machines are mechanical, industrial, & rigid.
