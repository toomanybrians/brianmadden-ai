# I spent a week using Dots. Here’s what I learned.

## Insights

- OpenAI's "Dots" personal agent collapses all interaction into a single abstracted thread with no model selection, no projects/folders, and all chat requests commingled — a deliberate bet that removing decision friction increases usage, even at the cost of mixing unrelated tasks (e.g., CRM work, travel research, sales prep) together.
- The product reflects a broader 2026 trend of abstracting away user choices (model, context organization) based on trust that the system will surface the right model and right context automatically, rather than requiring manual curation via folders/markdown files.
- Architecturally, Dots supports two computer-use modes (local machine vs. cloud computer), letting the agent pick whichever environment suits the task — addressing the limitation that local-only computer-use agents require an always-on machine.
- Each chat with Dots spawns a "sub-agent" — a separate orchestrated thread with its own context — which the author flags as possibly the most significant but least-understood feature of the product.
- Dots also pairs the single-thread design with a voice mode (GPT-Live), aiming to let users "ramble" and have the orchestrator spin up relevant sub-threads automatically, though the author found this buggy in practice.
- The author remains unconverted — still primarily using a competing agent ("Grok Bot") — but is intrigued by Dots' frontier model access and dual computer-use/orchestration architecture, calling himself "Dots Curious."

## Quote

> This one decision removes a lot of decision friction. Which is nice. Really nice.
