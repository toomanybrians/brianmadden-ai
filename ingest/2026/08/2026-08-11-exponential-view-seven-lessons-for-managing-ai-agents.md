# 🔮 Seven lessons for managing AI agents

## Insights

- Managing AI agents is emerging as a distinct skill: define an explicit, testable "finish line" before starting a task, since agents often declare work complete based on guessed or misread goals rather than actual criteria.
- Evaluative success criteria (e.g., "all 36 tests pass") outperform descriptive instructions (e.g., "make this more organized"); the same logic can extend to non-engineering deliverables via templates or structural specs.
- Not all tasks suit autonomous agent runs — when the desired output itself is unclear (e.g., ill-defined exploratory projects), goal clarification should precede delegation.
- Model selection should shift from "which model is best" to "where in the workflow does more intelligence actually change the outcome" — cheaper models can handle routine steps while stronger models set framing/parameters upfront.
- Effort/compute scaling shows steep diminishing returns (a jump from high to max effort doubled tokens for one benchmark point), reinforcing a rule of thumb: prefer a larger model at low effort over a smaller model maxed out.
- Token volume is a poor proxy for value; the piece proposes tracking a "quality-adjusted output" via weekly audits (tasks attempted, outputs used, costs, corrections, human-equivalent hours) to gauge real leverage — one cited case: $800 in agent costs replacing an estimated $19,000 and 48 hours of human work.

## Quote

> Tokens are a bit like electricity in a factory, measuring what goes in but not what comes off the production line.
