# Conceptual integrity and counting lines of code

## Insights

- Willison argues lines-of-code is a defensible productivity proxy because human output has a real ceiling: a great day pre-agents was ~200 lines of production-quality code, typical days 50-60; agents pushing that to 1,000 lines/day of equal quality is a meaningful gain.
- The new bottleneck with coding agents isn't code production speed but human cognitive capacity — engineers can generate code far faster than they can stay on top of it, which is why teams still need multiple engineers (load-balancing oversight, not just output).
- Coding agents threaten "conceptual integrity" (a Mythical Man-Month term for software where everything fits together with no surprises) because features that once took a week now take an hour, removing the natural discipline that time-cost used to impose on scope creep.
- The Winchester Mystery House is used as an analogy for agent-assisted software: cheap, easy incremental additions accumulate into a structure that loses coherence and becomes harder to reason about or make decisions on.
- A separate note argues the core skill for productive agent use is confidently instructing and verifying changes — not necessarily line-by-line code review, which is characterized as never having been the most effective validation method anyway.
- Enterprise adoption data cited elsewhere in the roundup: Anthropic's annualized revenue rose from $47bn (May) to $65bn (July) with 6,000 customers spending $100k+/year, while newer/pricier models (e.g. "Fable") saw lower usage share than cheaper predecessors per Ramp's billing-data index.
