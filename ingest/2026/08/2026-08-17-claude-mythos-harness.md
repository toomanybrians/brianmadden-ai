# HARNESS

## Insights

- Multiple AI vendors converged in the same short window (mid-August) on infrastructure for repeatable agent workflows rather than one-off prompts: OpenAI deprecated custom Codex prompts in favor of "Skills," Claude Code shipped built-in skills (/debug, /code-review, /batch, /loop, /verify), Google's ADK 2.0 moved to a graph-based workflow engine, and MCP's July 28 release added stateless architecture, long-running Tasks, and Skills over MCP.
- Alongside this, model releases were explicitly framed around agentic work: Google's Gemini 3.7 Flash (coding/agents workhorse), OpenAI's GPT-5.6 across its agent stack, and Anthropic's Fable 5, Opus 5, and Sonnet 5.
- The piece frames these as one underlying shift, not scattered updates: from "prompting" (telling AI what you want) to "harnessing" (giving AI a structured way to work).
- Core distinction offered: a good model can think, but a good harness makes that thinking repeatable — the harness is positioned as the missing infrastructure layer around model capability.
- Analogy introduced (cut off before fully developed): comparing an AI without a harness to a smart person placed in an empty room with only a single instruction, dependent entirely on prior knowledge.

## Quote

> A good model can think. A good harness can make that thinking repeatable.
