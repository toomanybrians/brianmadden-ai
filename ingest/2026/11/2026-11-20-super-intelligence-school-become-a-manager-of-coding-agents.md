# Become a Manager of Coding Agents

## Insights

- A coding agent can produce a patch and a passing test that both satisfy the literal ticket while still encoding the same underlying misunderstanding of the business logic — tests don't catch errors inherited from a flawed specification.
- The example (duplicate order rows distinguishing separate line items) shows that surface-level data problems ("one row too many") can mask a deeper ambiguity about what the data actually represents.
- The manager's real job precedes the coding step: clarifying the domain question (what counts as a separate purchase) before an agent writes any implementation.
- Once the domain question is resolved, the agent can be trusted to choose its own implementation approach — the human's leverage is in framing, not coding.
- A good acceptance test must validate against the real-world outcome (e.g., can the packer still identify both shirts) rather than a superficial metric like row count.
- This reframes "managing AI coding agents" as primarily a specification and verification discipline, not a technical/coding skill.

## Quote

> The code and the test agree because both inherited the same mistake from the brief.
