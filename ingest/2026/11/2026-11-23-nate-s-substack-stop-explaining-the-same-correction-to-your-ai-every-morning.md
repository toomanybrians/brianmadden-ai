# Stop explaining the same correction to your AI every morning. A guide and five prompts to find which of four causes sent your agent off track and make the fix stick

## Insights

- Major AI labs are now running agents for extended, unsupervised durations: OpenAI reports coding-agent sessions lasting hundreds of hours, Anthropic ran 1,000+ agents for eight days on an OS prototype, and Google describes extended Gemini-based engineering/research projects.
- The piece frames long-running agent work as requiring four capabilities: recognizing progress, receiving feedback, retaining what's been learned, and adapting when the goal or evidence changes.
- A common failure mode described: agents repeat corrected mistakes, ignore direction changes, and force the person overseeing them to keep re-explaining decisions — meaning an unsupervised eight-hour run can produce more rework rather than less.
- The author distinguishes between model capability, the "harness" around it, and context limits as separate factors determining whether a long chain of steps can catch and repair its own errors.
- When multiple people and their agents work on the same project, the problem compounds: individuals can each get better at using AI yet still end up with agents working from incompatible interpretations of shared decisions.
- The full (paywalled) piece promises a diagnostic framework (a four-cause table for agent errors), methods for writing shared "team rules" for agents, and a set of worksheets/prompts for coordinating multiple contributors' agents.

## Quote

> Give an agent like that eight hours on its own and you can end up with more work to repair.
