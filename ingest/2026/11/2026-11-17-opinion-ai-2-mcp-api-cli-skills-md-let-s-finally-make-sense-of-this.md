# MCP, API, CLI, Skills, .md… Let’s Finally Make Sense of This

## Insights

- The piece frames a common frustration — users seeing others get better results from "the same AI" they pay for — as a problem of missing tooling/setup rather than model choice or subscription tier.
- Argues that having "the right model" is insufficient if the AI lacks structured ways to access context, preferences, and feedback loops.
- Uses a concrete example: asking Claude to edit a personal website causes unwanted side-effect changes (rewritten paragraphs, broken spacing), illustrating the cost of giving an AI only a prompt with no persistent preferences or verification step.
- Proposes that a better setup includes three elements: a place for the AI to read stated preferences, a clear mechanism for making changes, and a way to verify/check the result afterward.
- Positions MCP, APIs, CLIs, and "skills" (and files like .md) as the practical pieces that fill this gap — tools to recognize and selectively apply based on the specific problem at hand, not something to adopt wholesale all at once.

## Quote

> You can have the right model and still be missing a piece.
