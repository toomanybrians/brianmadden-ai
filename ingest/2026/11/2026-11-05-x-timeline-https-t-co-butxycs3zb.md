# https://t.co/BUtXyCs3Zb

## Insights

- LifeOS is framed as an "AI harness" built on the premise that technology's goal should be human enhancement, not just task execution — positioned against AI that is "brilliant at executing" but doesn't know what the user actually wants.
- Core concept is "intent engineering" (vs. prompt engineering): a system captures a user's goals, context, and standards once (via a "TELOS" interview) and carries that context into every subsequent task/request.
- The operating loop is a four-step cycle — Articulate (define done via checkable criteria), Climb (take the next step), Verify (require tool-based evidence, not just claimed completion), Learn (feed outcomes back into the system) — applied uniformly to code, writing, health, or other life domains.
- Emphasizes verification over assertion: "evidence, or it did not happen" — steps must be proven via tool output rather than assumed to have worked.
- The system is architected as many composable named subsystems (Cortex for memory, Atlas for asset/security graphing, Ledger for versioned change tracking, Assay for eval/testing, Vigil for always-on monitoring, etc.), suggesting a broader platform vision beyond a simple coding assistant.
- Positioned as open-source (MIT License, on GitHub) and designed to be installed into existing AI coding tools (Claude Code, Cursor, Codex) via a single prompt or install script.

> From prompt engineering to intent engineering.
